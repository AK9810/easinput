这个版本只有一个新东西：托盘菜单里的「重启」。机器卡顿后如果气泡显示的模式和实际键入对不上，不用再自己退出重开了。

## 新增：托盘「重启」

菜单变成五项：`启用提示 / 开机自启 / 打开配置文件 / 重启 / 退出`。

点「重启」等于结束当前进程并立刻启动一个新的：重新读配置、重装钩子、重新播种 CapsLock 状态。
实测空窗 433–441ms，期间没有气泡；重启完成后弹一次托盘气泡「已重启」。

**为什么需要它。** 输入模式本身每次都是现读的，卡顿只会漏一次、下一轮轮询就补回来，不会永久错。
会永久错的只有两类状态：

- **CapsLock 锁定态**：只在启动时读一次，之后靠键盘事件翻转。漏一次事件就一直反向。
- **低级键盘钩子**：Windows 对钩子回调有超时，超时就**静默摘掉**，不通知程序。摘掉之后按键事件全丢。

这两种都只有重启进程才能恢复。所以这个菜单项做的是真重启，而不是在进程内重新初始化一遍状态——
后者需要人工维护一张清单，以后每加一处内存状态都要记得补，漏一处按钮就开始撒谎。理由记在
[ADR-0006](https://github.com/AK9810/easinput/blob/main/docs/adr/0006-restart-as-the-recovery-action.md)。

**失败兜底。** 新进程拉不起来时（比如 exe 被挪走了），当前进程**不退出**，弹气泡提示「重启失败」，
你可以再试一次或直接退出。旧进程会先把单实例互斥体交出去再启动新进程，新进程拿不到锁时最多等 3 秒，
不会出现「点了重启应用就没了」。

## 顺带的诊断

每次重启都会往日志里写一行 **Warn 级**快照，默认 `logLevel: warn` 也能看到：

```
[Warn] Restart: capsTracked=False capsSystem=False seeded=True mode=Chinese hwnd=0x40224 foregroundNow=0x40224 enabled=True showPending=False
[Warn] Keyboard hook: removed cleanly.
[Warn] Foreground hooks: removed=True/True.
```

- `capsTracked` 与 `capsSystem` 不一致 → CapsLock 计数漂移，气泡显示错的那个模式。
- 钩子那两行返回 `False` → 该钩子早已被系统摘掉，是另一种漂移。

把这几行贴到 issue 里，就能判断是哪一种。原因是这两类漂移只在重启那一刻还能被观测到。

## 已知边界

- 「重启」不做进程内状态重置，也不做钩子存活检测与自动重装。漂移仍然只能手动恢复。
- 提权窗口里的 CapsLock 与输入法切换，非提权进程本来就收不到/读不到，属于既有限制。
