# 气泡收紧为纯插入符语义

Status: ready-for-agent

本 spec 修订产品 spec（`.scratch/easinput/spec.md`）的「锚点降级」一节；该节自本 spec 定案起作废。
决策来源：2026-11-19 grilling 会话，Q1–Q4 全部定案。

## 问题陈述

用户点击桌面、文件夹空白处等非文本区域后切换输入模式时，蓝色药丸气泡出现在鼠标指针旁边。
它出现在与输入毫无关系的位置上，像误触弹窗，用户把它当 bug 报告。

机制澄清（防止修错层）：点击本身不是触发器——应用没有鼠标钩子。真实链路是：
点击别的窗口导致前台切换 → 新旧前台的有效状态变化（见 CONTEXT.md「有效状态变化」）→ 该弹；
而桌面没有插入符，锚点降级链的第三级「指针」（仅要求指针在焦点窗口内）把气泡挂到了鼠标旁。
要修的是锚点层的兜底语义，不是触发层。

## 方案

气泡只在锚点解析到**真实插入符**时显示。锚点降级链从四级减为三级：

Win32 插入符 → UIA 插入符 → 隐藏。

探测不到插入符的场景一律静默：桌面、游戏、只读网页、Qt/Java、远程桌面窗口。
同时删除「预览」功能（托盘菜单项与命令行参数）：其验收使命已完成，
且在纯插入符语义下多数场景会点了没反应，留着只会让用户以为按钮坏了。

## 用户故事

1. 作为桌面用户，我点击桌面或文件夹空白处后切换输入模式时，不希望气泡在鼠标旁弹出，因为那里不是我的输入位置。
2. 作为用户，我在没有文本插入符的场景（桌面、游戏、只读页面）按 CapsLock 或切中英文时，希望完全静默，符合「没有输入位置就没有提示位置」的直觉。
3. 作为用户，我在能探测到插入符的应用（记事本、VS Code、浏览器地址栏、Word）里切换模式时，气泡仍然出现在插入符正下方——既有核心体验不回退。
4. 作为用户，我接受在探测不到插入符但确实在打字的窗口（Qt/Java、远程桌面、ZCode 输入框、微信输入法自身输入框）里失去提示：宁可偶尔漏报，不可天天误报。
5. 作为维护者，我希望锚点降级链从四级减为三级，删掉一条在日常使用里几乎只产生误报的代码路径。
6. 作为维护者，我希望删除后不留配置开关，保持 v1 配置面最小；将来若真实场景疼痛，从版本历史捞回。
7. 作为用户，我打开托盘菜单时不再看到「预览效果」项，因为它的使命已完成，且在新语义下多数场景点了没反应。
8. 作为维护者，我希望预览相关的代码（入口、重试机制、仅预览使用的窗口归属判断）一并删净，不留死代码。
9. 作为实现代理，我需要明确「锚点失败不重试」：一次有效状态变化若因无锚点而未显示，就此消费掉，等下一次有效状态变化，不补弹。
10. 作为维护者，我希望 CONTEXT.md 与 ADR-0003 与新语义同步（删「指针」词条、锚点降级改三级），文档不再宣称四级链。
11. 作为用户，首次运行的托盘气泡提示不受本次改动影响，仍然保留。
12. 作为维护者，我希望验收矩阵中 ZCode/微信/只读网页各行的预期更新为 hidden，作为人工回归判据。

## 实现决策

- **纯插入符语义**：锚点解析只认两个插入符源（Win32 插入符、UIA 插入符），都失败即隐藏。
  指针级定位器、锚点层级枚举中的 Pointer 值、解析器的第三注入点全部删除。
- **触发机制不动**：CapsLock 按下、修饰键抬起、前台切换、300ms 轮询照旧；
  有效状态变化语义照旧。修复全部落在锚点层。
- **锚点失败不重试**：状态被消费就消费掉，不引入补弹或重试窗口。
- **预览整体删除**：托盘菜单「预览效果」、命令行 `--preview` 参数、控制器中的预览路径
  （含前台归属判断与 80ms×8 重试机制）全部移除。首次运行 balloon 与预览无关，保留。
- **配置面不变**：不新增、不删除任何配置字段。
- **文档同步**：CONTEXT.md 删「指针」词条、「锚点降级」改写为三级；
  ADR-0003 修订，记录理由：macOS 在同样场景下也在光标处弹出且长期被用户抱怨、无官方开关可关
  ——参照物在此点是反面教材，有意比它更严格。
- 代码与测试的逐文件落点见 grilling 会话定案（已固化），实现代理可直接按清单执行。

## 测试决策

- 好的测试只测外部行为：注入假定位器结果，断言解析出的锚点层级与矩形，不测内部调用顺序。
- 模块：Core 的锚点解析器。
- 回归核心用例：**两个插入符定位器都失败 → 期望 Hidden**（旧行为落 Pointer 层，
  正是「点桌面弹蓝泡」的防回归）。
- 既有优先级用例改写为双源（Win32 胜 UIA；Win32 失败落 UIA）。
- 端到端缝：`--probe` 诊断参数对真实窗口报告锚点层级 + 验收矩阵人工复测：
  Win32 EDIT → `Caret`；VS Code / Edge 地址栏 → `Uia`；ZCode / 微信自身输入框 / 只读网页 → `hidden`。
- 预览删除：编译 + 托盘菜单缺项 + `--preview` 参数被忽略（正常启动）的人工确认。
  App 层无自动化测试基建，不为本删除性改动新建（测试缝经确认：复用既有缝，不新建）。
- 先例：锚点解析器既有单测的假定位器注入缝。

## 范围外

- 不加指针兜底配置开关（明确否决：v1 少一个配置面就少一个测试与维护项）。
- 不做锚点失败重试/补弹（明确否决：时序复杂度不值得，下次状态变化还会弹）。
- 不做预览替代入口（明确否决：README 已有截图与配置说明，自演示使命完成）。
- UIA 只读判定、不注入远程线程的立场不变（ADR-0003 其余部分仍有效）。
- 远程桌面/Qt 场景若未来疼痛：从版本历史恢复指针级，属未来决策，v1 不做。
- 性能预算（57.7ms > 50ms）等其他未决项不在本 spec 内。

## 补充说明

- 决策核心权衡：误报天天遇到且像 bug；漏报偶尔发生且用户自己知道在打字、下次状态变化还会再弹。
- 旧产品 spec「锚点降级」一节（四级链）自本 spec 起作废，实现时无需回读。
- 定案记录（含机制澄清与逐文件清单）另存于会话记忆；本 spec 是唯一执行依据。
